# 数据集设计说明

## 为什么要做工况化采集

机械臂擦拭看起来是个"单一动作"，但实机部署时的失败往往来自**任务变量**而不是动作本身：

| 潜在失败原因 | 对应的工况类别 |
|---|---|
| 仪表装在不同位置 | 仪表位置偏移 |
| 仪表尺寸不同（大表盘 / 小表盘） | 仪表尺寸变化 |
| 表面干净 vs 布满油污，擦拭力度应不同 | 污渍状态判断 |
| 主从遥操作时海绵夹持位置不一致 | 海绵抓取偏差 |
| 车间顶灯 / 侧窗反光导致图像变化 | 光照/反光扰动 |
| 实验室背景与真实厂房不同 | 真实厂房采集 |
| 未预料到的实机失败 | 失败样本补录 |

**先做任务分析、推导出失败模式、再针对性设计采集方案**——这是这 201 条数据的核心价值。

## 构成

| # | 工况类型 | Episode 数 | 占比 |
|---|---|---|---|
| 1 | 标准污渍擦拭 | 27 | 13.4% |
| 2 | 仪表位置偏移 | 26 | 12.9% |
| 3 | 仪表尺寸变化 | 24 | 11.9% |
| 4 | 污渍状态判断 | 28 | 13.9% |
| 5 | 海绵抓取偏差 | 25 | 12.4% |
| 6 | 光照/反光扰动 | 23 | 11.4% |
| 7 | 真实厂房采集 | 24 | 11.9% |
| 8 | 失败样本补录 | 24 | 11.9% |
| | **合计** | **201** | 100% |

> 各工况数量刻意保持在 23–28 之间，**避免模型偏向某一类工况**。

## 采集方式

- **主从遥操作示教**：操作者通过主臂（`so101_leader`）控制从臂（`so101_follower`）完成任务，主从关节角度同步记录为专家动作；
- **双相机同步录制**：全局相机（`cam_high`，观察整体位置关系）+ 腕部相机（`cam_wrist`，补充海绵与仪表表面的局部接触信息），30 fps；
- **采集工具**：`lerobot-record`，键盘左键重录、右键提前结束、ESC 退出；
- **单条时长**：约 30–40 秒（`episode_time_s`）。

## 数据内容

每个 episode 包含：

| 字段 | 维度 | 说明 |
|---|---|---|
| 全局图像 | 640×480×3 | `cam_high` |
| 腕部图像 | 640×480×3 | `cam_wrist` |
| 关节状态 | 6 | 六个电机的角度 |
| 夹爪状态 | 1 | 开合程度 |
| 动作 | 6+1 | 示教动作（作为监督目标） |

## 迭代闭环（第 8 类数据的由来）

```
实机部署 → 发现失败案例 → 切换回录制模式补录 → 与旧数据混合（co-training）
        → 在上一版权重基础上低学习率微调 → 新权重 → 再次部署评估
```

这 24 条失败样本补录是**部署之后**回补的，因此它们的分布反映了模型真实的弱点，而不是我们预设的弱点。
